## Diagnostic Audit

### Concurrency

- [FACT] The application is a non-web Spring Boot command-line runner: `BenchmarkApplication.main` sets `WebApplicationType.NONE`, so the current runtime is not an HTTP request concurrent server by default. See [BenchmarkApplication.java](../src/main/java/org/benchmark/app/BenchmarkApplication.java#L23).
- [FACT] Mutable benchmark session state is centralized in `SessionStateManager`, which stores sessions in a `ConcurrentHashMap` and synchronizes on each `SessionData` instance before mutating or reading session-owned tool environments, execution logs, rejection logs, and attempt flags. See [SessionStateManager.java](../src/main/java/org/benchmark/exec/SessionStateManager.java#L46), [SessionStateManager.java](../src/main/java/org/benchmark/exec/SessionStateManager.java#L55), [SessionStateManager.java](../src/main/java/org/benchmark/exec/SessionStateManager.java#L108), [SessionStateManager.java](../src/main/java/org/benchmark/exec/SessionStateManager.java#L129), and [SessionStateManager.java](../src/main/java/org/benchmark/exec/SessionStateManager.java#L322).
- [FACT] `ToolEnvironment` is mutable and not internally synchronized; it uses `LinkedHashSet` and `LinkedHashMap` fields for declared keys and values. Current thread safety depends on callers going through `SessionStateManager` locks. See [ToolEnvironment.java](../src/main/java/org/benchmark/exec/ToolEnvironment.java#L16) and [ToolEnvironment.java](../src/main/java/org/benchmark/exec/ToolEnvironment.java#L33).
- [FACT] `BenchmarkRunSummary` uses plain mutable counters and totals (`int` and `double`) plus a mutable `ArrayList`. See [BenchmarkRunSummary.java](../src/main/java/org/benchmark/runner/BenchmarkRunSummary.java#L12). This is safe only under the current sequential runner loop in [BenchmarkRunner.java](../src/main/java/org/benchmark/runner/BenchmarkRunner.java#L97).
- [INFERENCE] If case execution is parallelized later, `BenchmarkRunSummary` should be redesigned with `AtomicInteger`, `LongAdder`, `DoubleAdder`, or per-case immutable results followed by a reduction step. This follows from the mutable non-atomic fields in [BenchmarkRunSummary.java](../src/main/java/org/benchmark/runner/BenchmarkRunSummary.java#L13) and the current aggregation writes in [BenchmarkRunSummaryAggregator.java](../src/main/java/org/benchmark/runner/BenchmarkRunSummaryAggregator.java#L40).
- [FACT] A single shared `Random` bean is injected into generator components. See [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L29), [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L41), [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L62), [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L74), [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L86), [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L97), and [BenchmarkGenerationConfig.java](../src/main/java/org/benchmark/config/BenchmarkGenerationConfig.java#L118).
- [INFERENCE] The shared `Random` supports repeatable generation when `benchmark.random-seed` is set, but concurrent generation would make random draw ordering depend on scheduling. The seed is configured in [application.yml](../src/main/resources/application.yml#L23) and bound by [BenchmarkProperties.java](../src/main/java/org/benchmark/config/BenchmarkProperties.java#L27).

## Overview

### System Purpose

- [FACT] The project is a Java Spring Boot benchmark harness that generates synthetic proprietary CLI-like tools, gives an LLM a generated manual and goal, exposes in-process tool callbacks, simulates command execution, scores behavior, and writes local artifacts. This is visible in the runner flow in [BenchmarkRunner.java](../src/main/java/org/benchmark/runner/BenchmarkRunner.java#L57), case generation in [BenchmarkCaseGenerator.java](../src/main/java/org/benchmark/gen/BenchmarkCaseGenerator.java#L132), tool callback creation in [BenchmarkCaseToolCallbackFactory.java](../src/main/java/org/benchmark/tools/runtime/BenchmarkCaseToolCallbackFactory.java#L31), execution simulation in [CliSimulator.java](../src/main/java/org/benchmark/exec/CliSimulator.java#L36), scoring in [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L80), and artifact writing in [BenchmarkRunArtifactWriter.java](../src/main/java/org/benchmark/runner/BenchmarkRunArtifactWriter.java#L20).
- [FACT] Documentation quality is represented by the `DocumentComplexity` enum with `CLEAN`, `INCOMPLETE`, `UNSTRUCTURED`, and `LOGICAL_CONFLICT` profiles. See [DocumentComplexity.java](../src/main/java/org/benchmark/model/enums/DocumentComplexity.java#L6).
- [FACT] The current configuration sets the benchmark to four iterations, eight distractor tools, eight maximum execution attempts, one command execution per attempt, deterministic random seed `33`, manufacturing domain, clean documentation, and trap-command mode enabled. See [application.yml](../src/main/resources/application.yml#L15).

### Core Flow

- [FACT] Case generation starts in `BenchmarkCaseGenerator.generateCases`, which selects a domain and scenario pattern, resolves variables, creates a target tool, creates semantic decoys and random distractors, builds a case manual, and returns immutable `BenchmarkCase` records. See [BenchmarkCaseGenerator.java](../src/main/java/org/benchmark/gen/BenchmarkCaseGenerator.java#L132).
- [FACT] Prompt construction starts with `BenchmarkPromptBuilder.buildInitialMessages`, which inserts the configured base system prompt, generated case manual, session id, user goal, and current state into external templates. - [FACT] LLM execution uses `LlmClient.execute`, which disables Spring AI internal tool execution and attaches the available callbacks to the `OpenAiChatOptions`. See [LlmClient.java](../src/main/java/org/benchmark/llm/LlmClient.java#L99).
- [FACT] The benchmark executor manually dispatches model-requested tool calls by matching tool-call names to callbacks returned by the provider. See [BenchmarkCaseExecutor.java](../src/main/java/org/benchmark/exec/BenchmarkCaseExecutor.java#L136) and [BenchmarkCaseExecutor.java](../src/main/java/org/benchmark/exec/BenchmarkCaseExecutor.java#L151).
- [FACT] Command execution runs through policy checks before simulator mutation: `BenchmarkToolExecutionService.executeCommand` rejects second execution in the same attempt, unknown tools, unknown commands, repeated failures, budget violations, and already-complete scenarios before invoking `CliSimulator`. See [BenchmarkToolExecutionService.java](../src/main/java/org/benchmark/tools/server/BenchmarkToolExecutionService.java#L29), [BenchmarkToolExecutionService.java](../src/main/java/org/benchmark/tools/server/BenchmarkToolExecutionService.java#L36), [BenchmarkToolExecutionService.java](../src/main/java/org/benchmark/tools/server/BenchmarkToolExecutionService.java#L45), [BenchmarkToolExecutionService.java](../src/main/java/org/benchmark/tools/server/BenchmarkToolExecutionService.java#L52), [BenchmarkToolExecutionService.java](../src/main/java/org/benchmark/tools/server/BenchmarkToolExecutionService.java#L58), and [BenchmarkToolExecutionPolicy.java](../src/main/java/org/benchmark/tools/server/BenchmarkToolExecutionPolicy.java#L24).

### Autonomous Execution and Retry Protocol

- [FACT] The system prompt instructs the model to include a short assistant message with tool calls, call `executeCommand` exactly once while the goal is incomplete, and avoid analysis-only answers when another command is needed. See [benchmark-system.st](../src/main/resources/prompts/benchmark-system.st#L3).
- [FACT] The runtime guardrail configuration instructs the model not to repeat failed commands, to respect preconditions, to use `getCurrentState` when needed, to call `executeCommand` exactly once while incomplete, and to keep `executeCommand` calls within the configured limit. See [application.yml](../src/main/resources/application.yml#L36).
- [FACT] After each attempt, retry feedback is built from latest executions and current session state only. See [BenchmarkAttemptFeedbackBuilder.java](../src/main/java/org/benchmark/prompt/BenchmarkAttemptFeedbackBuilder.java#L11) and [BenchmarkAttemptFeedbackBuilder.java](../src/main/java/org/benchmark/prompt/BenchmarkAttemptFeedbackBuilder.java#L33).
- [FACT] The executor appends retry messages only after the first attempt. See [BenchmarkCaseExecutor.java](../src/main/java/org/benchmark/exec/BenchmarkCaseExecutor.java#L64).

### Dependent Metrics

- [FACT] Final case score contains tool selection, step completion rate, ordering accuracy, state accuracy, efficiency, command precision, decoy resistance, recovery flag, and passed flag. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L29).
- [FACT] The composite score averages six primary metrics and excludes decoy resistance. The source comment states this preserves historical composite baselines while rolling out the new metric. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L40).
- [FACT] Passing is equivalent to `goalAchieved`, and `goalAchieved` requires full step completion, full ordering accuracy, and exact expected-state match. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L80) and [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L148).
- [FACT] Step completion checks whether each required target-tool command had at least one successful execution. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L163).
- [FACT] Ordering uses the longest increasing subsequence of successful target-step indices. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L188) and [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L348).
- [FACT] State accuracy compares the expected final state with the current target-tool state. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L221).
- [FACT] Efficiency is computed as required steps divided by weighted executions, failed executions count as `1.5`, and active traps add two expected steps. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L236).
- [FACT] Command precision divides required target-tool executions by all executions. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L256).
- [FACT] Decoy resistance subtracts `0.60` for successful state-mutating semantic-decoy executions and `0.25` for other semantic-decoy probes. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L281).
- [FACT] Recovery is true when the recovery command was used or when the first attempt failed and the goal was later achieved. See [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L93).

## Notable Limitations and Edge Cases

- [FACT] If `benchmark.iterations` is zero or negative, summary averages return `0.0`, but case generation will create no cases because the `for` loop in `generateCases` will not execute. See [BenchmarkRunSummaryAggregator.java](../src/main/java/org/benchmark/runner/BenchmarkRunSummaryAggregator.java#L93) and [BenchmarkCaseGenerator.java](../src/main/java/org/benchmark/gen/BenchmarkCaseGenerator.java#L139).
- [FACT] If a workflow references an unknown family, workflow, or option profile id, catalog resolution throws an `IllegalStateException`. See [ToolCatalog.java](../src/main/java/org/benchmark/gen/catalog/ToolCatalog.java#L29), [ToolCatalog.java](../src/main/java/org/benchmark/gen/catalog/ToolCatalog.java#L42), and [ToolCatalog.java](../src/main/java/org/benchmark/gen/catalog/ToolCatalog.java#L49).
- [FACT] A transient model call failure is translated by `LlmClient`; `BenchmarkCaseExecutor` catches `LlmServiceException` and treats it as a failed attempt. See [LlmClient.java](../src/main/java/org/benchmark/llm/LlmClient.java#L136) and [BenchmarkCaseExecutor.java](../src/main/java/org/benchmark/exec/BenchmarkCaseExecutor.java#L119).
- [FACT] An unknown callback requested by the model raises `LlmToolCallbackException`. See [BenchmarkCaseExecutor.java](../src/main/java/org/benchmark/exec/BenchmarkCaseExecutor.java#L139).
- [FACT] Missing token usage metadata is converted to zero with a warning. See [LlmClient.java](../src/main/java/org/benchmark/llm/LlmClient.java#L128).
- [FACT] Empty assistant messages are replaced by a tool-call summary or `<no assistant message>`. See [LlmClient.java](../src/main/java/org/benchmark/llm/LlmClient.java#L172).
- [FACT] JSON serialization failures and artifact-writing failures are logged as warnings rather than terminating the run. See [BenchmarkEventLogger.java](../src/main/java/org/benchmark/logging/BenchmarkEventLogger.java#L64) and [BenchmarkRunArtifactWriter.java](../src/main/java/org/benchmark/runner/BenchmarkRunArtifactWriter.java#L26).

## Thesis-Ready Summary

- [FACT] The benchmark operationalizes proprietary CLI execution by generating synthetic tools, commands, options, state variables, documentation, and task goals rather than using an external real CLI. The relevant generation path is [BenchmarkCaseGenerator.java](../src/main/java/org/benchmark/gen/BenchmarkCaseGenerator.java#L132), with command naming in [CommandAbbreviator.java](../src/main/java/org/benchmark/gen/tool_generator/CommandAbbreviator.java#L11) and stateful execution in [CliSimulator.java](../src/main/java/org/benchmark/exec/CliSimulator.java#L36).
- [FACT] The methodology can treat documentation quality as a controlled independent variable because the same simulator semantics can be rendered through four documentation profiles. See [DocumentComplexity.java](../src/main/java/org/benchmark/model/enums/DocumentComplexity.java#L6) and [DocumentationGenerator.java](../src/main/java/org/benchmark/gen/doc_generator/DocumentationGenerator.java#L27).
- [FACT] Autonomous recovery is measurable because the executor runs multiple attempts, appends retry feedback from runtime evidence, and scores final success plus recovery. See [BenchmarkCaseExecutor.java](../src/main/java/org/benchmark/exec/BenchmarkCaseExecutor.java#L58), [BenchmarkAttemptFeedbackBuilder.java](../src/main/java/org/benchmark/prompt/BenchmarkAttemptFeedbackBuilder.java#L33), and [BenchmarkScorer.java](../src/main/java/org/benchmark/scoring/BenchmarkScorer.java#L93).

See [BenchmarkEventLogger.java](../src/main/java/org/benchmark/logging/BenchmarkEventLogger.java#L64), [BenchmarkRunArtifactWriter.java](../src/main/java/org/benchmark/runner/BenchmarkRunArtifactWriter.java#L20), and [logback-spring.xml](../src/main/resources/logback-spring.xml#L18).
